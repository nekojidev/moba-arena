# Протокол гри, версія 1

Керувальні повідомлення (`join`, `welcome`, `roster`, `chat`, `ping`/`pong`, `events`) —
текстові кадри WebSocket із JSON `{ "v": 1, "type": … }`. Ігрові повідомлення — `input` і
`snapshot` — бінарні кадри, описані тут. Клієнт може попросити JSON і для них
(`"codec": "json"` у `join`) — лише для порівняння.

Усі багатобайтові числа — **little-endian**. Перший байт кожного бінарного кадру — версія
протоколу, другий — тип.

## `input` (клієнт → сервер), 8 байтів

| Зсув | Тип | Поле                                             |
| ---- | --- | ------------------------------------------------ |
| 0    | u8  | версія = 1                                       |
| 1    | u8  | тип = 1                                          |
| 2    | u32 | `seq` — номер input, зростає на 1                |
| 6    | u8  | кнопки: біт 0 тяга, 1 гальмо, 2 ривок, 3 постріл |
| 7    | i8  | поворот: −1, 0 або 1                             |

Кадр іншої довжини, з іншими бітами кнопок або поворотом поза −1…1 — помилка протоколу,
сокет закривається з кодом 4000.

## `snapshot` (сервер → клієнт)

Заголовок, 10 байтів:

| Зсув | Тип | Поле                                                |
| ---- | --- | --------------------------------------------------- |
| 0    | u8  | версія = 1                                          |
| 1    | u8  | тип = 2                                             |
| 2    | u32 | `tick` — номер кроку сервера                        |
| 6    | u32 | `ack` — `seq` останнього обробленого input адресата |

Власний герой адресата, 32 байти (якщо біт 0 прапорців не виставлено — решта нулі):

| Зсув | Тип | Поле                                                                    |
| ---- | --- | ----------------------------------------------------------------------- |
| 10   | u8  | прапорці: біт 0 є, 1 «лежить», 2 щит, 3 швидкий вогонь, 4 самонаведення |
| 11   | u8  | `hp`                                                                    |
| 12   | f32 | `x`                                                                     |
| 16   | f32 | `y`                                                                     |
| 20   | f32 | `vx`                                                                    |
| 24   | f32 | `vy`                                                                    |
| 28   | i16 | `angle` (див. нижче)                                                    |
| 30   | f32 | `dashCooldown`, с                                                       |
| 34   | f32 | `fireCooldown`, с                                                       |
| 38   | f32 | `respawnTimer`, с                                                       |

Далі `u16` — кількість сутностей, і стільки ж записів. Спільна частина запису, 12 байтів:

| Зсув | Тип | Поле                                                     |
| ---- | --- | -------------------------------------------------------- |
| 0    | u32 | `id`                                                     |
| 4    | u8  | вид: 0 герой, 1 снаряд, 2 голем, 3 руна                  |
| 5    | u8  | прапорці: біт 0 «лежить», 1 щит, 2 тяга, 3 самонаведення |
| 6    | u16 | `x` × 16                                                 |
| 8    | u16 | `y` × 16                                                 |
| 10   | i16 | `angle`                                                  |

Хвіст запису залежить від виду:

| Вид    | Байтів | Поля                                               |
| ------ | ------ | -------------------------------------------------- |
| герой  | 3      | u8 `hp`, u16 `score`                               |
| снаряд | 4      | u32 `owner` — id героя                             |
| голем  | 1      | u8 `size` (1…3)                                    |
| руна   | 1      | u8 ефект: 0 щит, 1 швидкий вогонь, 2 самонаведення |

## Квантування

- **Кут** — `i16 = round(angle / π × 32767)`, кут попередньо зведено до `[−π, π)`.
  Крок 2π / 65534 ≈ 9.6·10⁻⁵ рад ≈ 0.0055°. На відстані 1000 одиниць це 0.1 одиниці —
  менше за піксель.
- **Позиція чужих сутностей** — `u16 = round(x × 16)`, крок 1/16 одиниці. Арена не ширша за
  3000 одиниць, тож значення не перевищує 48 000 і вміщається в `u16`. Ці позиції лише
  малюються (з інтерполяцією), у фізиці клієнта не беруть участі.
- **Власний герой** — `f32` без квантування позиції й швидкості: з цього стану клієнт
  заново програє непідтверджені input, і похибка тут множилася б із кожним кроком.
